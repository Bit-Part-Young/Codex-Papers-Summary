## 文献总结

### 1. 研究背景与目标

机器学习原子间势（MLIP）试图在第一性原理计算精度与大规模分子动力学（MD）模拟效率之间取得平衡，但现有 MLIP 软件生态高度碎片化。不同势函数架构往往对应不同代码库、输入格式、训练流程与部署接口，这使得统一比较、复现实验和跨框架工作流构建都较为困难。本文的目标是提出一个统一、可扩展、同时兼顾训练与推理性能的 MLIP 框架 AI2Pot，用于连接模型开发、训练、评估和大规模 MD 部署。

### 2. 核心思想与技术路线

AI2Pot 的核心思想是为不同 MLIP 架构建立统一计算后端。作者没有采用通用自动微分去处理代价高昂的原子尺度算子，而是针对 MTP 和 NEP 的核心算子，以手写的 C++/CUDA 方式分别重构训练与推理流程，并让训练与推理共享同一套算子后端。这样做的直接收益包括：

- 减少训练与推理实现不一致的问题；
- 避免缓存大量中间张量，从而降低显存或内存占用；
- 提升性能关键原子尺度算子的执行效率；
- 将高性能原子模拟计算与 PyTorch / PyTorch Lightning 的现代机器学习生态连接起来。

### 3. 统一理论表述

AI2Pot 将不同 MLIP 模型统一写成“局域描述符到原子能”的映射：

- 体系总能量被分解为各原子能之和；
- 每个原子的局域环境用一组描述符表示；
- 原子能写作 $E_i = f_\theta(D_{i,k})$；
- 力由总能对原子坐标的负梯度给出；
- 维里张量由原子能对坐标导数一致计算得到。

在这一框架下，MTP 与 NEP 的差异主要体现在映射函数 $f_\theta$ 和描述符构造方式上，而能量、力、维里计算路径在实现层面保持统一。

### 4. MTP 与 NEP 的实现特点

#### 4.1 MTP

AI2Pot 中的 MTP 基于 Shapeev 的原始 MTP 与 MLIP-v3 实现，但对径向切换函数等细节做了改动。其主要特征包括：

- 以系统构造的基函数线性展开原子能；
- 通过矩张量描述符编码邻域环境；
- 用 $r_\mathrm{max}$ 和 $r_\mathrm{min}$ 定义截断与平滑区间；
- 使用改进的切换函数，使得在截断半径处不仅函数连续，而且一阶与二阶导数也消失，从而改进力和维里计算稳定性。

#### 4.2 NEP

AI2Pot 中的 NEP 基于 Fan 提出的原始 NEP 形式重新实现。其主要特征包括：

- 用单隐层神经网络预测原子能；
- 描述符由径向两体项与角向多体项组成；
- 当前实现中角向展开截断到 $l_\mathrm{max} = 4$；
- 当前描述符集合只包含二体与三体项；
- 通过球谐加法定理构造三体角向描述符。

作者强调，AI2Pot 在 NEP 中构造角向中间量的计算模式，与 MTP 中矩张量描述符的模式保持一致，从而实现跨模型的统一描述符后端。

### 5. 损失函数与优化策略

训练损失在构型层面同时包含能量、力与维里三部分。总损失为三者加和，并由权重 $w_E$、$w_F$、$w_V$ 控制相对贡献。优化方面：

- 使用 PyTorch Lightning 组织训练流程；
- MTP 与 NEP 都纳入统一的一阶梯度优化框架；
- 示例训练中使用 Adam 优化器；
- 学习率采用“线性 warmup + 余弦退火”两阶段调度；
- 损失项权重随训练步动态变化，早期更强调力项，后期逐渐提升能量与维里项的相对权重。

### 6. 软件架构与工作流

AI2Pot 采用分层架构：

- 顶层是 PyTorch / Lightning 前端，负责模型定义、训练控制、检查点与评估；
- 中间层是共享的 C++/CUDA 核心算子，负责描述符构造、能量、力、维里与训练相关计算；
- 底层是 ASE 与 LAMMPS 的部署接口。

训练阶段，AI2Pot 采用按原子并行的执行范式，并在每一步在线构造邻居表，不做缓存。作者指出，这种设计更接近 MD 模拟本身，也增强了训练与推理的一致性。当前实现支持 CPU 或单 GPU 训练；推理侧则已支持基于 MPI 的多 GPU 执行，但并行性能尚待未来系统评估。

### 7. AI2Pot-cli 的作用

作者同时提供了 AI2Pot-cli 作为上层命令行工具，用于：

- 安装与数据预处理；
- 训练输入生成；
- 后处理；
- 常见工作流的低配置执行。

文中给出的示例表明，用户可通过极少命令快速生成训练输入并启动 MTP 训练。作者也明确说明，当前版本的 AI2Pot-cli 尚未集成主动学习与 MD 实用工具，这些功能留待后续开发。

### 8. 数据集与测试设置

文中使用 Ge-Sb-Te 三元体系数据集验证框架性能：

- 训练集：2633 个 frames，合计 283465 个原子；
- 测试集：673 个 frames，合计 85821 个原子；
- 覆盖晶态、液态与非晶构型，以及不同化学成分；
- 标签包括第一性原理能量、原子力和维里张量；
- 硬件平台为 Intel Xeon Platinum 8352Y CPU @ 2.20 GHz 与 NVIDIA GeForce RTX 4090 D GPU。

### 9. 主要结果

#### 9.1 MTP 训练结果

MTP 使用默认 AI2Pot-cli 配置、batch size = 1，MTP level 为 18，Ge-Sb-Te 三元素组合下共有 526 个可训练参数。结果为：

- 训练集 RMSE：
  - 能量：21.79 meV/atom
  - 力：243.86 meV/Å
  - 维里：74.40 meV/atom
- 测试集 RMSE：
  - 能量：25.03 meV/atom
  - 力：207.69 meV/Å
  - 维里：46.38 meV/atom

作者认为，这说明默认配置下的 MTP 已能在该数据集上取得合理预测精度。

#### 9.2 NEP 训练结果

NEP 使用默认 AI2Pot-cli 配置、batch size = 1，总计 7.9k 个可训练参数。结果为：

- 训练集 RMSE：
  - 能量：12.74 meV/atom
  - 力：176.38 meV/Å
  - 维里：47.58 meV/atom
- 测试集 RMSE：
  - 能量：16.47 meV/atom
  - 力：156.28 meV/Å
  - 维里：31.22 meV/atom

相较于文中使用的紧凑型 MTP 模型，这一 NEP 模型在 Ge-Sb-Te 数据集上取得了更高预测精度。

#### 9.3 batch size 对精度与效率的影响

对于 MTP：

- 力的 RMSE 在整个 batch-size 范围内几乎不变；
- 能量与维里误差对 batch size 更敏感；
- batch size = 32 时，能量训练误差比基线升高到约 1.3；
- 维里误差比则单调恶化至约 1.4。

对于 NEP：

- 力 RMSE 随 batch size 增大有中等幅度上升；
- 测试集力误差比在 batch size = 32 时升至 1.13；
- 能量误差更敏感，训练误差比升至约 1.5；
- 维里误差比同样单调恶化至约 1.4。

总体上，大 batch size 可明显加快训练，适合早期快速探索；小 batch size 更适合最终高精度模型训练。

#### 9.4 训练时间比较

在文中所选模型配置下，MTP 训练速度快于 NEP。以小时计：

- batch size = 1：MTP 5.93，NEP 8.93
- batch size = 2：MTP 3.40，NEP 5.48
- batch size = 4：MTP 1.90，NEP 3.32
- batch size = 8：MTP 1.40，NEP 3.07
- batch size = 16：MTP 0.90，NEP 2.07
- batch size = 32：MTP 0.75，NEP 1.30

作者提醒，这一比较反映的是本文具体模型配置下的行为，不代表势函数形式本身的绝对优劣。

#### 9.5 MD 推理性能

在单 GPU 上，MTP 和 NEP 都可以通过 LAMMPS 执行百万原子级别 MD 模拟，但 NEP 的大体系推理吞吐明显更高：

- 189 个原子时：
  - MTP：16.6 katom-step/s
  - NEP：15.3 katom-step/s
- 3.4 百万个原子时峰值：
  - MTP：355.3 katom-step/s
  - NEP：923.5 katom-step/s

NEP 峰值吞吐约为 MTP 的 2.6 倍。作者将 MTP 推理较慢主要归因于当前 CUDA 实现中 moment tensor 描述符带来的更大局域内存需求、更高寄存器压力和更重的本地内存流量。Nsight Compute 剖析还表明，两类推理 kernel 都主要受 L2 cache 内存流量限制，而 MTP 的瓶颈更突出。

### 10. 结论与意义

本文提出的 AI2Pot 将高性能原子尺度计算与现代 PyTorch 生态结合起来，为 MTP 和 NEP 提供了统一训练与部署后端，并通过 Ge-Sb-Te 数据集和 LAMMPS 大规模 MD 演示了其实用性。其主要意义在于：

- 降低不同 MLIP 架构之间的工作流割裂；
- 保持训练与推理一致性；
- 在单 GPU 上支持百万原子级模拟；
- 为后续将更多 MLIP 架构纳入统一框架提供了可扩展基础。

同时，文中也清楚指出若干边界：当前训练仅支持 CPU 或单 GPU，AI2Pot-cli 尚缺主动学习与 MD 实用功能，多 GPU 并行性能仍需后续专门评估。

## 摘要翻译

机器学习原子间势（MLIPs）在第一性原理计算的精度与大规模分子动力学（MD）模拟所需的效率之间架起了桥梁。然而，现有的 MLIP 软件在不同模型架构之间仍然是碎片化的，这使得建立支持灵活模型开发、高效训练和可扩展 MD 部署的统一工作流变得困难。在这里，我们提出 AI2Pot，这是一个可扩展且统一的 MLIP 框架，它将模型训练、评估和大规模 MD 模拟与兼容 PyTorch 的生态系统无缝集成。AI2Pot 不依赖于通用自动微分去处理代价高昂的原子尺度算子，而是使用手工编写的 C++/CUDA 代码，针对矩张量势（MTP）和神经进化势（NEP）的核心计算同时重构了训练与推理流程。这些专用算子构成了一套由训练与推理共享的统一计算后端，从而提高了训练与推理的一致性，并通过避免大型中间缓存而降低了内存占用。基于 Ge-Sb-Te 体系的基准测试证明了 AI2Pot 的精度与效率。通过 LAMMPS 部署后，AI2Pot 能够在单个 GPU 上对包含数百万原子的原子体系进行 MD 模拟。此外，AI2Pot 还提供配套的命令行工具 AI2Pot-cli 和 Python API，以促进实际 MLIP 工作流的开展。通过将高性能原子计算与现代机器学习生态系统统一起来，AI2Pot 为大规模 MD 的 MLIP 开发、训练与部署提供了一个用户友好的端到端框架。

## 引言翻译

分子动力学（MD）模拟为研究原子尺度材料的动力学性质和热力学行为提供了一种强有力的方法。MD 模拟的可靠性与效率在很大程度上取决于原子间势。第一性原理分子动力学（AIMD）通过从电子结构计算中评估原子相互作用而提供高精度，但其计算成本限制了可处理的体系尺寸与时间尺度。相比之下，经验势在计算效率方面显著更高，但通常存在精度有限以及在多样化化学环境中可迁移性较差的问题。

在过去几十年中，基于第一性原理数据训练得到的机器学习原子间势（MLIPs）已经成为一种极具吸引力的替代方案，能够在精度与计算成本之间提供有利平衡。具有代表性的 MLIP 架构包括 Behle-Parrinello Neural Network potential（BPNN）[1]、Gaussian approximation potentials（GAP）[2]、Moment Tensor Potential（MTP）[3]、Atomic Cluster Expansion potentials（ACE）[4]、Deep Potential（DP）[5] 以及 Neuroevolution Potentials（NEP）[6]。这些模型已经成功应用于广泛的材料问题，例如相变 [7–9]、合金 [10–12]、电池 [13–15] 等。近年来，基于图神经网络的通用势和基础模型，例如 M3GNet [16]、CHGNet [17]、MACE [18] 和 DPA 系列模型 [19]，进一步扩展了 MLIP 的适用范围，使其能够在多样化化学空间中进行可迁移预测。

尽管如此，不同的 MLIP 架构在精度与计算成本之间仍表现出不同权衡。基于 GNN 的模型通常通过消息传递获得较高精度，但其相对较高的推理成本限制了它们在复杂微结构大规模 MD 模拟中的应用，例如晶界、位错和器件尺度体系。相比之下，较具可扩展性的 MLIP，例如 MTP、ACE、DP 和 NEP，通常采用更局域化的描述符，以在精度和速度之间取得较有利的平衡。例如，ACE、DP 和 NEP 已经实现了涉及数百万到万亿原子的超大规模模拟 [20–23]。这些进展凸显了可扩展 MLIP 模型的重要性。

然而，高效且可扩展的 MLIP 的开发仍然分散在彼此割裂的软件生态中 [21,24–26]。不同势模型常常实现于相互独立的代码中，每一套代码都有自己的输入格式、训练流程和部署接口。这种碎片化给那些希望在统一工作流中对多个 MLIP 框架进行基准测试、比较或集成的用户带来了实质性障碍。此外，许多 MLIP 软件包依赖相对封闭的软件基础设施，与 PyTorch [27] 和 PyTorch Lightning 等现代机器学习生态的整合程度有限，而这些生态中已经提供了成熟的优化、调度、日志、分布式训练和工作流管理组件。因此，当前的 MLIP 开发与训练通常缺乏标准机器学习流水线所具备的灵活性、模块化和可扩展性。这些软件层面的不兼容性进一步阻碍了将第一性原理数据生成、MLIP 训练、模型评估和 MD 部署无缝连接起来的统一工作流的构建。

在这里，我们提出 AI2Pot（Ab Initio & Artificial Intelligence Potential），这是一个可扩展且统一的 MLIP 框架，用于连接 MD 模拟中的模型训练、评估和部署。AI2Pot 通过自定义 C++/CUDA 算子和兼容 PyTorch 的训练工作流，对广泛使用的 MTP 和 NEP 模型提供统一支持。作为概念验证，我们以 Ge-Sb-Te 数据集为例展示该框架，并系统评估其 GPU 加速训练效率和分子动力学推理性能。

## 方法翻译

### 2. 理论

#### 2.1 机器学习原子间势的一般表述

AI2Pot 为 MLIP 提供了一种统一表述，使不同类型的模型能够在一致的计算框架中实现能量、力和维里的评估。与 MLIP 的传统表述一致，在 AI2Pot 中，体系总能量被分解为各原子贡献之和：

$$
E_\mathrm{tot} = \sum_i^N E_i
$$

其中，$E_i$ 表示原子 $i$ 的原子能，由其截断半径内的局域环境决定。

原子 $i$ 的局域原子环境用一组描述符 $\{D_{i,k}\}$ 表示，其中 $k$ 表示描述符索引。原子能写为统一函数形式：

$$
E_i = f_\theta(D_{i,k})
$$

其中，$f_\theta$ 表示一般的可学习映射。$f_\theta$ 的具体形式取决于所选 MLIP 架构。对于 MTP，$f_\theta$ 被表述为描述符上的线性展开；而对于 NEP，$f_\theta$ 则由非线性神经网络表示。在这一表述下，不同 MLIP 架构共享从描述符到能量的计算方案，仅在可学习映射函数 $f_\theta$ 上有所不同。

原子力通过总能对原子位置的负梯度得到。应用链式法则后，沿笛卡尔方向 α 的原子 $i$ 所受力可以写为原子能关于各描述符的导数与描述符关于原子坐标导数的求和形式。这里，$r_{ij} = r_j - r_i$ 是原子 $i$ 与 $j$ 之间的相对位置矢量，求和遍历截断半径内所有满足 $j \ne i$ 的原子。

维里张量分量 $V_{\alpha,\beta}$，其中 α 与 β 表示笛卡尔方向，也通过原子能导数以一致方式计算得到。

#### 2.2 矩张量势

AI2Pot 中的 MTP 实现遵循 Shapeev 提出的原始表述以及后续 MLIP-v3 实现 [3,25]，同时对径向切换函数和其他实现细节进行了修改，以改善性能并增强与 AI2Pot 框架的整合。MTP 使用一组系统构造的基函数对原子能进行线性建模。模型复杂度由 MTP level 控制，它决定了基函数数量。

对于每个原子 $i$，矩张量描述符通过汇总截断半径内邻近原子的贡献来构造。径向截断由两个参数 $r_\mathrm{max}$ 与 $r_\mathrm{min}$ 定义，其中 $r_\mathrm{max}$ 是原子相互作用消失的截断半径，$r_\mathrm{min}$ 标记平滑切换区的起始位置。描述符分量由中心原子与近邻原子种类、Chebyshev 多项式基和相对位置张量积共同构成。

其中的径向项由 Chebyshev 多项式与切换函数共同定义，归一化距离由 $|r_{ij}|$、$r_\mathrm{max}$ 和 $r_\mathrm{min}$ 决定。

AI2Pot 中 MTP 的切换函数被设计为改善截断边界处的数值光滑性。与 MLIP-v3 中原始 MTP 实现相比，这里不仅要求函数在截断半径处连续，还要求其一阶与二阶导数在该处消失，从而改善力和维里评估的稳定性。

随后，矩张量描述符通过预定义的张量收缩方案进一步构造成标量不变量基函数。这些基函数构成 MTP 的表示空间，并用于原子能的线性展开。在 AI2Pot 中，这一收缩规则遵循 MLIP-v3 中的表述。

#### 2.3 神经进化势

AI2Pot 中重新实现的 NEP 基于 Fan 提出的原始 NEP 表述 [6]。在 NEP 模型中，原子能由作用于一组旋转不变描述符上的单隐层神经网络预测，其中隐层神经元数设为 $N_\mathrm{neurons}$。描述符集合包括径向（二体）描述符和角向（多体）描述符，其中 $n$ 表示径向基函数索引，而 $l$ 与 $m$ 表示球谐展开中的阶数和级数。径向与角向基函数的数量分别由对应参数指定。

作为神经网络模型，NEP 并不严格要求描述符集合在数学上完备，因为非线性神经网络能够从紧凑描述符表示中有效学习复杂原子相互作用。在 AI2Pot 当前实现中，角向展开截断到 $l_\mathrm{max} = 4$，且描述符集合只包含二体项与三体项。

径向描述符通过对截断半径内近邻贡献求和得到，其中包含化学组分相关系数、Chebyshev 多项式与 NEP 切换函数。归一化距离由 $|r_{ij}| / r_\mathrm{max}$ 构造。NEP 的切换函数在 $|r_{ij}| \le r_\mathrm{max}$ 范围内采用余弦型平滑形式，在截断之外取零。

角向描述符基于球谐函数加法定理构造。作者首先定义一个包含实球谐基函数的中间量，然后将其平方加权求和得到最终三体描述符。在 AI2Pot 中，这一角向中间量的构造遵循与 MTP 矩张量描述符相同的计算模式，从而保证不同 MLIP 模型在框架内部具有统一描述符后端。

#### 2.4 损失函数

AI2Pot 中势模型训练的损失函数定义在构型层面，将能量、力与维里三部分统一到同一个目标函数中。总损失写为：

$$
L_\mathrm{total} = L_E + L_F + L_V
$$

其中，能量损失、力损失和维里损失分别由对应预测值与参考值之间的平方误差构成，$w_E$、$w_F$ 和 $w_V$ 是平衡三部分贡献的权重因子。

### 3. AI2Pot 框架与实现

#### 3.1 架构

如图 1 所示，AI2Pot 采用分层架构，将高层 MLIP 模型开发与性能关键型原子尺度计算分离开来。图 1 的顶层是 PyTorch / Lightning 前端，它为用户提供模型定义、训练、检查点保存和评估等组件。该层保留了 PyTorch 生态系统的灵活性，并使 AI2Pot 能够自然地与现代机器学习工作流集成。

图 1 中的核心计算层包含自定义 C++/CUDA 算子。这些算子负责描述符构造、能量评估、力计算、维里计算以及训练相关操作。AI2Pot 的一个关键设计原则是，训练和推理共享同一套算子后端。这种统一后端避免了模型优化与部署之间的差异，改进了训练与推理一致性，也减少了维护两套实现所需的工程负担。

前端与自定义后端之间的连接通过 Torch 绑定实现。该接口使自定义算子能够直接参与 PyTorch 训练流水线，同时保留性能关键计算由 C++/CUDA kernel 高效执行的优势。底层则提供面向分子动力学应用的推理与部署接口。训练后的模型可部署到 LAMMPS 和 ASE 等外部模拟引擎中，从而使 AI2Pot 的支持范围超出模型开发阶段。总体而言，这一架构建立了一条从模型训练到高性能推理与 MD 部署的完整路径。

#### 3.2 共享的 C++/CUDA 训练与推理算子

AI2Pot 核心 C++/CUDA 算子的计算设计遵循按原子执行范式，如图 2 所示。与深度学习框架中常见的张量并行策略不同，AI2Pot 将独立计算任务分配给每一个中心原子。这种按原子计算模式直接映射到其底层 C++/CUDA kernel 的设计中。

在这一框架中，所有核心算子都被实现为由训练与推理共享的统一 C++/CUDA kernel，从而保证不同执行阶段之间的数值一致性。同一套算子同时复用于模型优化与 MD 推理，避免了前向与反向计算的冗余实现。AI2Pot 中所有算子都同时支持 float32 和 float64 精度，其正确性已通过 PyTorch 的 `torch.autograd.gradcheck()` 梯度检查验证。

图 3 展示了核心训练算子随体系尺寸变化的性能标度行为。作者以 Ge2Sb2Te5 立方超胞为基准体系，比较了 CPU 上 OpenMP 并行与 GPU 上 CUDA 加速的表现。对于 MTP 训练算子，16 与 32 线程 OpenMP 相对单线程可获得约 3 倍到 6 倍加速，并且对体系尺寸依赖较弱；GPU 在 99 个原子时即可达到接近 10 倍加速，并随体系尺寸继续上升。对于 NEP 训练算子，16 与 32 线程 OpenMP 可获得约 5 倍到 8 倍加速；GPU 加速进一步增强，在 99 个原子时约为 14 倍，在 900 个原子时达到 125.38 倍，而 MTP 在相同规模时为 77.96 倍。作者将这一差异归因于 MTP 的矩张量描述符具有更高内存开销，而 NEP 的中间量内存需求更低。

作者总结认为，GPU 执行为大超胞训练提供了有利的标度行为，同时在小体系上也保持竞争力。基准测试中 GPU 尚未完全饱和，说明通过增大 batch size 仍可进一步提升训练速度。

#### 3.3 优化协议

AI2Pot 的 MLIP 训练流水线基于 PyTorch Lightning 实现，从而为训练控制提供灵活且模块化的接口。这种设计使优化器配置、学习率调度、动态损失加权、梯度裁剪和基于 callback 的操作都可以在统一且可复现的框架中实现。

##### 3.3.1 优化器配置

AI2Pot 的优化策略不同于若干代表性 MLIP 实现中的传统工作流。在原始 MTP 框架中，模型通常通过 BFGS 类非线性优化与线性系数最小二乘更新相结合来优化 [25]；后续 MTP 实现也使用过 L-BFGS 与最小二乘求解器 [28,29]。相比之下，AI2Pot 将 MTP 模型的所有参数都视为可学习张量，并在 PyTorch 训练框架中通过一阶基于梯度的优化器直接优化。

对于 NEP，原始 GPUMD 实现使用基于神经进化的优化 [21]，而后续发展已经引入了 AdamW 等基于梯度的优化器 [30,31]。AI2Pot 延续这一方向，并为 MTP 与 NEP 提供统一优化器接口，使不同势模型能够在同一优化框架下训练。

在本文示例中，模型参数使用 Adam 优化器进行优化。优化器施加于每个 MLIP 模型的全部可学习参数，初始学习率为 $lr_\mathrm{start}$。指数滑动平均系数设置为 $β_1 = 0.9$ 与 $β_2 = 0.999$，数值稳定常数固定为 $ε = 10^{-8}$。训练过程中不施加权重衰减。这一配置为线性 MTP 与神经网络型 NEP 都提供了稳定且鲁棒的优化框架。

##### 3.3.2 学习率调度

AI2Pot 采用由线性预热阶段和余弦退火衰减阶段组成的两阶段学习率调度。学习率在每一个训练步更新，调度由初始学习率 $lr_\mathrm{start}$ 和最终学习率 $lr_\mathrm{end}$ 参数化。

引入预热阶段是为了稳定训练早期优化，并避免梯度更新过于突兀。该阶段通过 PyTorch 中的 `LinearLR` 调度器实现，学习率从固定起始因子 $1 \times 10^{-4}$ 线性增加至 $lr_\mathrm{start}$，预热持续时间设为 1 个 epoch。预热之后，学习率通过 PyTorch 中的 `CosineAnnealingLR` 采用余弦退火方式，从 $lr_\mathrm{start}$ 逐步衰减到 $lr_\mathrm{end}$。这种设计保证了从快速初始适应到稳定细化收敛的平滑过渡。整个学习率调度流程通过重写 PyTorch Lightning 的 `LightningModule` 类中的 `configure_optimizers()` 方法实现。

##### 3.3.3 动态损失加权

AI2Pot 使用动态损失加权策略，以平衡训练过程中能量、力和维里三部分损失的贡献。权重在每一个训练步根据预设初值和终值之间的线性插值进行更新。能量、力和维里损失的权重都与当前学习率相关联，因此在训练早期，力项往往具有更大权重；随着学习率降低，能量和维里项的相对权重逐渐增强。

#### 3.4 训练执行工作流

AI2Pot 的训练执行工作流如图 4 所示。AI2Pot 采用在线邻居表构建策略而不进行缓存，这一点与 MD 模拟中的处理模式高度一致，因此能够保证训练与推理之间的一致性。训练开始时，原子结构通过 ASE 接口从 Extxyz 文件中读入。在每一个训练步，原子结构首先被解析并传递给 AI2Pot 邻居表类 `ai2pot.core.Nblist`，以动态构造局域原子环境。随后，这些数据被转移到目标计算设备（CPU 或 GPU），由 AI2Pot 算子执行能量、力和维里的前向评估，再通过反向传播完成参数优化。

由于在线邻居表构建和基于算子的计算具有较高内存效率，当前实现仅支持在 CPU 或单 GPU 上训练。作者同时给出了一个最小 Python 脚本示例，说明如何通过 `Trainer`、`ExtxyzDataset`、`ExtxyzDatamodule` 和 `LitLinearMtp` 在默认超参数下训练 MTP 模型。

#### 3.5 在 ASE / LAMMPS 中的模型导出与部署

AI2Pot 提供统一的模型导出与部署框架，以实现跨 ASE 和 LAMMPS 的一致推理，如图 5 所示。相同的训练后模型参数在所有部署后端之间共享，但 ASE 与 LAMMPS 使用不同的序列化格式。

对于 ASE，AI2Pot 模型通过 PyTorch Lightning checkpoint 部署。这种格式保留了完整模型灵活性，包括动态图和可配置精度。相对地，LAMMPS 部署依赖通过 `torch.jit.script()` 编译得到的 TorchScript 静态 `.pt` 文件。为了保证执行稳定性与 C++ 运行时兼容性，LAMMPS 推理被限制为单精度浮点。尽管这种方式在灵活性上弱于基于 checkpoint 的执行，但在大规模分布式模拟中显著提升了稳健性。

对于基于 ASE 的模拟，AI2Pot 为 MTP 和 NEP 都提供了兼容 Python 的 calculator。运行时，原子结构先在 CPU 上处理，并使用 `ai2pot.core.Nblist` 以线性复杂度构建邻居表，然后将邻居信息转移到目标设备（CPU 或 GPU），再评估能量、力和维里。计算得到的能量以标量返回，力与维里则转换为 NumPy 数组供后续处理。

对于 LAMMPS 集成，AI2Pot 通过标准 `pair_style` 接口调用。LAMMPS 中每个 MPI 进程映射到一个计算设备（CPU 或 GPU）。邻居表在 CPU 上针对各局域区域构建，再转为 Torch 张量以供 GPU 推理。之后，算得的能量、力和维里回传给 LAMMPS 引擎，用于大规模 MD 模拟。总体而言，AI2Pot 在不同部署后端上复用了相同训练模型与核心算子，仅对序列化格式进行了适配。

#### 3.6 AI2Pot-cli

AI2Pot 提供的是一个集成到广泛计算生态中的 Python 接口，用于访问高性能原子模拟与机器学习例程；而 AI2Pot-cli 则建立在这一接口之上，作为更高层的命令行封装，用于实现标准化、低配置的工作流执行。AI2Pot-cli 受到 VASPKIT 这类工作流导向界面的启发，可作为交互式与脚本式执行的统一入口。

如图 6 所示，AI2Pot-cli 界面首先给出横幅区域，展示软件名、版本、开发者信息及 AI2Pot 和 AI2Pot-cli 的仓库链接，以保证可追溯性、版本可控性和复现性。主界面按模块组织功能，包括安装、数据预处理、训练输入生成、后处理和分子动力学工具等。用户既可以通过执行 `ai2pot-cli` 进入交互式菜单模式，也可以通过脚本方式工作。文中给出示例，说明一个 MTP 模型只需两条命令即可完成训练准备与训练启动。

作者指出，当前版本的 AI2Pot-cli 尚未包括主动学习功能与 MD 实用工具，这些功能将在未来版本中加入。总体上，AI2Pot-cli 为 AI2Pot 框架中的数据准备、模型构建、评估和部署之间搭建了一个轻量且便捷的工作流接口。

## 结论翻译

在这项工作中，我们提出了 AI2Pot，这是一个可扩展且统一的机器学习原子间势（MLIP）框架，它将高性能原子尺度计算集成到基于 PyTorch 的生态系统之中。通过重新优化按原子执行的 C++/CUDA 算子，并将其与 PyTorch 和 PyTorch Lightning 前端整合，AI2Pot 能够在保留现代机器学习工作流灵活性的同时，高效执行性能关键的 MLIP 算子。

至关重要的是，该框架为矩张量势（MTP）和神经进化势（NEP）建立了统一计算后端，使不同 MLIP 架构能够通过一致的软件接口进行训练和部署。AI2Pot 的能力通过一个包含晶态、液态和非晶构型的 Ge-Sb-Te 数据集得到了展示。在 AI2Pot-cli 生成的默认训练配置下，MTP 和 NEP 模型都获得了合理的预测精度。文中还进一步评估了 batch size 对训练精度和效率的影响。增大 batch size 会显著缩短 MTP 和 NEP 的训练时间，但也可能降低精度。

此外，通过 LAMMPS 接口开展的大规模分子动力学模拟展示了 AI2Pot 的可扩展性与计算效率。部署到 LAMMPS 中的 AI2Pot 模型可在单个 GPU 上实现包含数百万原子的原子体系模拟，其中 MTP 和 NEP 的峰值速度分别达到 355.3 和 923.5 katom-steps/s。结合 AI2Pot-cli，该框架为从第一性原理数据集到面向实际应用的 MLIP 训练与大规模分子动力学部署提供了一条便捷的端到端路径。归根结底，AI2Pot 不仅为材料科学家提供了一个高效工具，也建立了一个统一计算框架，用于连接高性能原子模拟与现代机器学习生态系统，从而支持灵活且高效的 MLIP 应用。
